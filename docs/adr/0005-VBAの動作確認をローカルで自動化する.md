# ADR-0005: VBA の動作確認はユーザの PC で自動実行し、その記録を CI で照合する

- 日付: 2026-10-16
- ステータス: 採用（2026-10-16）

## 文脈

- VBA の教材コードも、実行して確かめる必要がある（REQ-02 CR-09, AC-03）。
- VBA の実行には Excel が要る。CI（GitHub Actions）の実行環境には Excel がない。
- ユーザの回答（REQ-02 K9）により、VBA の確認は Claude がユーザの PC の Excel を自動操作して行う。
- Excel を外部から操作して VBA を取り込むには、Excel の設定「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」を有効にする必要がある。この設定は、悪意のあるマクロにも同じ操作を許してしまう。

## 検討した選択肢

### 案A: ユーザの PC で確認ツールを実行し、確認記録（ソースのハッシュ値と結果）をリポジトリに入れる。CI は記録と現在のソースを照合する

- 利点: 未確認の VBA が公開されるのを CI で止められる
- 欠点: VBA を変えるたびに、ユーザの PC での確認が必要

### 案B: ユーザの PC で確認するが、記録は残さない

- 欠点: 確認したかどうかを後から確かめられず、確認漏れを防げない

### 案C: Windows と Excel の入った CI 環境を用意する

- 欠点: 費用と Office のライセンスの問題があり、月額0円の制約に合わない

## 決定

案A を採用する。ツールは PowerShell で作り、Excel を COM 経由で操作する。

- 上記の Excel 設定は、ツールが確認の前に有効にし、終了時（失敗時を含む）に無効に戻す（REQ-02 NFR-10）。
- `Debug.Print` の出力は外から取り出せないため、ツールは確認用の写しの中でだけ `Debug.Print` を出力収集用の手続きに置き換え、集めた出力を期待結果と照合する（DES-01 §9.2）。
- 確認記録には、VBA のソースと期待結果の両方のハッシュ値を入れる。期待結果だけを変えた場合も、確認し直さないと CI を通らない。

## 理由

費用をかけずに確認を自動化でき、記録の照合によって確認漏れを公開前に止められる。設定を有効にしておく時間を確認作業の間だけに限ることで、リスクを小さくする。

## 結果と影響

- 得られること: VBA の確認の自動化と、確認漏れの防止
- 諦めること・受け入れる制約: VBA の教材の更新には、ユーザの PC（Windows・Excel）が必要
- 見直す条件: ユーザの PC で Excel が使えなくなったとき（手作業での確認に戻すことになるが、REQ-02 NFR-10・AC-03 の変更になるため、ユーザに相談する）

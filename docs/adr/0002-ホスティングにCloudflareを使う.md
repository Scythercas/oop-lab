# ADR-0002: ホスティングに Cloudflare を使う

- 日付: 2026-10-16
- ステータス: 採用（2026-10-16）

## 文脈

- 初回は静的サイトとして配信する（ADR-0001）。運用費は月額0円。
- 教材のレビューのため、Pull Request ごとに実際の画面を確認できるとよい（DES-01 §6.1）。
- 将来、ログイン・採点・ランキングをサーバ側の機能として追加する。費用の上限は月額5,000円。採点の方式（コード実行／AI）は未定（REQ-02 RQ11）。

## 検討した選択肢

| 観点 | Cloudflare | GitHub Pages | Firebase | Vercel ／ Netlify |
| --- | --- | --- | --- | --- |
| 静的配信を無料で | ○ | ○ | ○（転送量に無料枠の上限あり） | ○（無料枠に上限あり） |
| Pull Request ごとのプレビュー | ○ | ×（標準機能ではない） | △（プレビュー用の仕組みを別に設定） | ○ |
| 将来のサーバ機能 | ○ サーバレス関数・データベース・キー値ストア。有料プランも月額5ドル程度から | × 別のサービスが必要 | ○ サーバ関数・データベース・認証。サーバ関数は従量課金プランへの登録が必要 | ○ サーバ関数あり。データベース・認証は外部サービス |
| 認証 | △ 自前の実装か外部サービス | × | ◎ 組み込みの認証機能 | △ 外部サービス |
| コード実行による採点（RQ11 の「コードを実行して採点」） | △ コンテナ実行機能（有料プラン） | × | △ 別のサービスと組み合わせ | × |
| 規約上の注意 | 特になし | 特になし | 特になし | Vercel の無料プランは非商用のみ |

## 決定

Cloudflare を使う。具体的な製品（Workers の静的アセット配信／Pages）と、無料枠・料金の数値は、実装に着手するときに公式情報で確認し直す。

## 理由

- 初回の静的配信とプレビューを無料で満たし、将来のサーバ機能（API・データベース）も同じ基盤の上に、月額5,000円の上限内で足せる見込みがある。
- 採点の方式が未定なので、AI の API 呼び出しにもコード実行にも道がある基盤を選んだ。
- 認証は Firebase のほうが楽だが、認証は将来の1機能にすぎない。外部の認証サービスを組み合わせることもできる。

## 結果と影響

- 得られること: 初回0円、プレビュー URL によるレビュー、将来の拡張の道
- 諦めること・受け入れる制約: 将来の認証は、自前で作るか外部サービスを選ぶ必要がある。Cloudflare のアカウント管理がユーザの作業として増える
- 見直す条件: 将来機能に着手する時点で、料金体系が変わって月額5,000円に収まらなくなったとき。または認証の実装負担が大きすぎると判断したとき（その場合は Firebase などを再検討する）

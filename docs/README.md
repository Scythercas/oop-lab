# 設計ドキュメント

オブジェクト指向学習Webアプリの仕様書・設計書を置く。

## 進め方（作業ルール）

- **「必ず実装して」の指示があるまでは実装（コード作成）を行わず、仕様書・設計書の作成だけを行う。**
- 一般的なウォーターフォール型の手順（V字モデル）に沿って進め、前工程の成果物が合意されてから次工程に進む。
- 根幹に関わる不明点は推測で埋めない。各文書の「未決事項」に書いて確認する。
- 要求定義書・要件定義書の各記述には出典区分を付ける。設計書（基本設計以降）と ADR は、ユーザが確認するまで文書全体を【提案】として扱い、ユーザの決定に基づく箇所は要件定義書などの ID で出典を示す。

| 出典区分 | 意味 |
| --- | --- |
| 【原文】 | ユーザ（発注者）の発言そのもの |
| 【解釈】 | 原文を Claude が整理・言い換えたもの（確認が必要） |
| 【提案】 | Claude の提案（未承認） |
| 【決定】 | ユーザの合意が取れたもの |
